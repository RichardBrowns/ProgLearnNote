# 概述

## 什么是Docker？

Docker 是一个开源的平台，通过容器技术，使得应用程序可以在任何环境中运行，而不受底层操作系统的限制。

## 为什么要使用Docker？

- **资源利用率高**
  - 容器比传统的虚拟机更加轻量级，因为它们共享操作系统内核，不需要运行完整的操作系统实例。
- **快速部署和扩展**
  - 使用Docker可以快速部署应用程序，因为容器启动速度很快。
- **一致性和可移植性**
  - Docker 容器确保应用程序在开发、测试和生产环境中具有一致的运行环境。
- **隔离性和安全性**
  - 容器提供进程和文件系统的隔离，确保应用程序之间不会互相干扰。

## 什么是镜像？

Docker 镜像（Image）是一个只读的模板，用于创建 Docker 容器。镜像包含了运行应用程序所需的所有文件、依赖、配置和环境设置。它是 Docker 中的核心组件之一，提供了应用程序及其依赖环境的标准化封装。

**主要特点**

1. **层（Layer）**：
   - Docker 镜像由多个层组成，每一层代表镜像构建过程中执行的一条指令。
   - 这些层是只读的，并且可以被多个镜像共享，从而提高了存储和传输的效率。
2. **不可变性**：
   - 镜像是不可变的，一旦创建就不能更改。如果需要修改镜像，必须基于现有镜像创建一个新的镜像。
3. **轻量级**：
   - 由于镜像是由多个层组成的，Docker 只会存储和传输那些在多个镜像之间共享的层，从而减少了存储空间和网络带宽的消耗。

## 什么是容器？

镜像（`Image`）和容器（`Container`）的关系，就像面向对象程序设计中`类`和`对象`一样，镜像是静态的定义，容器是镜像运行的实体。容器可以被创建、停止、删除。

容器的实质是进程，但是与直接在宿主执行的进程不同，容器进程拥有自己独立的命名空间，运行在其中的应用就像运行在一个独立的操作系统一样。容器拥有自己的`root`文件系统，自己的网络配置、自己的进程空间，甚至自己的用户ID空间。

每一个运行的容器，以镜像为基础层，在其上创建一个当前容器的存储层，也成为容器存储层。

容器存储层的生存周期和容器一样，容器消亡时，容器存储层也随之消亡。因此，任何保存于容器存储层的信息都会随容器删除而丢失。

**容器存储层保持无状态化**

1. **无状态化容器：**
   - 无状态化意味着容器本身不保存任何持久数据。所有的数据存储都应该在容器外部进行管理。这种方法确保了容器的可移植性和灵活性，因为容器可以随时停止、重启或替换，而不会丢失数据。
2. **容器存储层：**
   - 容器存储层是容器运行时的文件系统层。默认情况下，所有在容器内的写操作都会写到这个层。然而，这个层是临时的，当容器被删除或重新创建时，这些数据也会丢失。

**使用数据卷和绑定宿主目录**

为了避免数据丢失并提高性能和稳定性，Docker 提供了两种主要方法来管理持久数据：

1. **数据卷**

   - 数据卷是由 Docker 管理的专用存储，可以在容器之间共享和重用。卷存在于 Docker 主机的文件系统中，但独立于任何特定的容器。

   - 使用数据卷的好处包括：持久性、数据共享、备份和恢复、以及更好的性能。

     ```bash
     # 创建一个数据卷
     docker volume create my_volume
     
     # 使用数据卷运行容器
     docker run -d --name my_container -v my_volume:/app/data my_image
     ```

2. **绑定宿主目录**

   - 绑定宿主目录将宿主机的特定目录加载到容器内的某个目录。与数据卷不同，绑定宿主目录直接映射到宿主机的文件系统路径。

   - 使用绑定宿主目录的好处是可以直接访问和使用宿主机上的文件和目录。

     ```bash
     # 使用绑定宿主目录运行容器
     docker run -d --name my_container -v /path/on/host:/app/data my_image
     ```
